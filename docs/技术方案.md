# 技术方案：考虑用户意愿的 V2G 智能调度平台

> 本文档是完整的技术设计说明，可用作面试深度问答的准备材料。
> 所有公式与代码实现一一对应（模块标注在括号内）。

## 1. 问题定位

大规模电动汽车无序充放电会加剧配电网负荷波动、增大峰谷差并导致电压越限；
而 V2G（Vehicle-to-Grid）潜力的释放又受制于**用户参与意愿的异质性**。
本平台在统一仿真内核上，比较四类调度范式的三方效益（电网 / 用户 / 充电站）：

| 范式 | 方法 | 感知电网 | 处理意愿 | 求解时机 |
|---|---|---|---|---|
| 无管理 | 无序充电（基线） | ✗ | ✗ | — |
| 价格响应 | 分时电价启发式 | ✗ | ✓（放电门槛） | 在线规则 |
| 集中式优化 | 改进 MOPSO | ✓ | ✓（意愿→功率上限） | 日前 |
| 数据驱动 | PPO 强化学习 | ✓ | ✓ | 日前训练/在线滚动 |

与本人 ACPEE 2026 会议论文的关系：论文解决"建模 + 单一算法"，
本平台将其工程化为**可复现的开源系统**，并新增强化学习范式与三方对比。

## 2. 系统架构（`v2g/` + `algorithms/`）

```
scenario.py ──► 蒙特卡洛出行链场景（EV 事件表）
                    │
                    ▼
willingness.py ─ 模糊逻辑意愿量化 w(i,t) ∈ [0,1]     ┐
                    │                                │ 共享
                    ▼                                │ CRN
environment.py ─ V2GSim 仿真内核（两层：站点功率→单车分配）
                    │                   │
                    ▼                   ▼
grid.py ────── 线性化 DistFlow 潮流    metrics.py ─ 指标
        ▲               ▲
        │               │
uncoordinated / tou_response / mopso / ppo（四种策略）
```

关键设计：**同一场景下所有算法使用完全相同的 EV 集合与意愿矩阵**
（公共随机数法 CRN），对比差异只来自调度策略本身。

## 3. 模型

### 3.1 EV 与出行链（`scenario.py`）

- 电池容量 `E_i ~ LogNormal(ln 55, 0.25²)` kWh，截断 [30, 100]
- 日行驶里程 `km_i ~ LogNormal(ln 42, 0.55²)` km → 到站 SOC = 1 − 0.15·km/E
- 出行链窗口（时间 15 min 粒度）：
  - 夜间住家窗口：昨夜 `t_in1 ~ N(19, 1.5²)` h 到达，今晨 `t_out1 ~ N(7.3, 1²)` h 离场（跨 0 点）
  - 35% 车辆有白天单位/公共窗口 `[t_in2, t_out2] ⊂ [9.5, 17.5]` h，两段行驶能耗按 `U(0.3,0.7)` 比例分配
  - 离场 SOC 需求 `SOC_need ~ N(0.75, 0.12²)`，为**硬约束**（违约计罚）

### 3.2 意愿量化（`willingness.py`）

延续论文思路，Mamdani 型模糊推理，输入：

1. **SOC 裕度** x₁ = (SOC − SOC_need)/(SOC_max − SOC_need)：电池退化焦虑
2. **停留裕度** x₂ = (τ_剩 − τ_需)/(τ_剩 + τ_需)，其中 τ_需 = 亏缺电量/额定功率：时间焦虑
3. **电价水平** x₃ ∈ {谷=0, 平=0.5, 峰=1}：补偿激励

三条三角/肩形隶属函数 × 9 条规则（单点输出 0.05–0.90），强度加权解模糊，
再叠加峰时激励修正 ±0.15。**意愿度直接映射为可调度放电容量系数**：
`P_dis_max(i,t) = w(i,t) · P_dis` 且 `w ≥ 0.5` 才开放 V2G——
把"用户是否愿意"这一软约束转译为优化/RL 可用的硬边界。

> 实现说明：意愿矩阵以"无序充电自然轨迹"为参考离线量化，
> 同一场景内四种算法共用（CRN 一致性）；在线滚动修正列为后续工作。

### 3.3 电网模型（`grid.py`）

IEEE 33 节点 radial 系统（MATPOWER `case33bw`，3.715 MW + j2.3 MVAr），
6 座充电站分布于三条馈线（节点 7/12/17/20/24/30，1-based）。

采用 **线性化 DistFlow**（Baran–Wu）：

- 支路潮流：`P_k = Σ_{下游} P_i`，`Q_k = Σ_{下游} Q_i`（拓扑求和矩阵 A 一次预计算）
- 电压：`V_j ≈ 1 − Σ_{路径} (r_k P_k + x_k Q_k)/V₀²·S_base⁻¹`
- 网损：`P_loss = Σ_k r_k (P_k² + Q_k²)/V_LL²`

**标定**（无 EV、基础负荷峰值时刻）：线性化模型最低电压 0.920 p.u.
（精确潮流 0.9131 p.u.，误差 0.7%），最低电压节点 18 号（与文献一致）。
线性化使得单次全天潮流 <2 ms，可嵌入 PSO/RL 循环；
`grid.verify_pandapower()` 保留精确交流潮流校验接口。

### 3.4 两层调度（`environment.py`）

上层决策为站点级功率 `P_s(t)`；下层分配规则：

- **充电**：紧迫度 = 亏缺能量/(剩余在站时间) 降序依次满足（cumsum 前缀和向量化实现）
- **放电**：意愿度降序，受 `P_dis_max(i,t)`、SOC 下限与"离场底线"约束

**防违约的事前约束（放电底线抬升）**：若剩余时间已不足以从下限充回
SOC 需求，则底线由 0.10 抬至 SOC_need；白天窗口离场前底线为 0.35
（保证返家可达）。这使违约在约束层面被阻断，而非仅靠目标函数惩罚。

### 3.5 三目标（`metrics.py` / `mopso.py`）

```
f1 = 电网运行成本 = C_loss·Σ网损 + W·负荷方差          （min）
f2 = 用户综合成本 = Σ[充电电费 + 退化成本 − V2G 补偿]   （min）
f3 = 电站收益     = 充电服务毛利 + V2G 售电收益 − 补偿支出 （max）
```

电价：谷 0.31 / 平 0.62 / 峰 1.05 元/kWh；用户充电价 = TOU×1.4；
V2G 补偿 0.70 元/kWh；退化成本 0.12 元/kWh 吞吐。

## 4. 算法

### 4.1 改进 MOPSO（`algorithms/mopso.py`）

决策变量 X ∈ [−1,1]^{6×96}（站点功率指令），解码后由仿真内核自动满足
个体约束。相对标准 MOPSO 的改进：

1. 惯性权重线性递减 0.9 → 0.4
2. 以概率 0.1 高斯变异扰动（跳出局部最优）
3. 外部档案（上限 50）+ 拥挤距离维护多样性，gbest 按拥挤距离轮盘选择
4. 模糊隶属度法选择最终折衷解：maximize min_i μ_i(f_i)

复杂度：每代 30 次仿真 × 60 代，单场景约 2 分钟（含潮流与指标）。

### 4.2 PPO 强化学习（`algorithms/ppo.py`）

**MDP 建模**
- 状态（39 维）：全局 9 维（时刻 sin/cos、电价、基础负荷、接入规模、
  聚合 SOC、聚合亏缺、上步动作均值）+ 每站 5 维（车辆数/均 SOC/亏缺/
  充电裕度/放电裕度）
- 动作：a ∈ [−1,1]⁶，>0 充电、<0 放电，幅值 = 占该站当前可调容量比例
- 奖励：`r = −(网损/50 + 电压越限×20 + 用户成本/20 − 电站收益/20) − 8×违约数`

**训练**：clip-PPO，GAE(λ=0.95)，MLP(128,64) 高斯策略，优势标准化，
梯度裁剪 0.5；15 万步（约 1560 个"天"）。**域随机化**：每个回合
重新采样出行场景，提升对随机性的泛化；评估在 CRN 场景上确定性执行。

### 4.3 对比实验设计（`run_experiment.py`）

- 5 个 CRN 场景 × 4 种策略，报告均值 ± 标准差
- 指标：峰值负荷、峰谷差、网损、电压偏差、户均成本、电站收益、
  V2G 电量、离场达标率
- 结果与全部图表落盘 `results/`，Streamlit 大屏（`app/dashboard.py`）可视化

## 6. 已知局限与扩展方向（面试常问）

1. **意愿离线量化**：以无序充电轨迹为参考，未做在线滚动修正 →
   扩展：滚动时域内重估 w，或用强化学习直接学习"补偿-参与"博弈
2. **线性化潮流**：重载下误差 ~1%（0.92 vs 0.913）→ 已保留
   pandapower 精确校验，可切换内环精确潮流（以计算换精度）
3. **确定性等价**：RL 用单场景确定性评估，未报告分布鲁棒指标 →
   扩展：多场景期望 + CVaR 风险度量
4. **无通信时延/隐私建模** → 扩展：联邦学习版多站协调（每站本地训练）
5. **规模**：160 车/6 站；可平移到 104 节点/数千车（A@ 矩阵按拓扑自动生成）
