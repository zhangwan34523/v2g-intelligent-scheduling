# 硬件扩展指南（选做）：智能充电桩边缘节点

> 目的：把"纯软件平台"升级为"数字孪生 + 边缘节点"的软硬件闭环演示。
> 这是电气类保研面试中极少人有的差异化亮点，但属于锦上添花，
> 时间紧张可整体跳过。预计投入：3–5 天（基于你已有的 STM32 经验）。

## 1. 演示逻辑（面试 3 分钟剧本）

```
[上位机大屏]  PPO/MOPSO 输出 15min 站点功率指令
      │ MQTT (发布 dispatch/station_1)
      ▼
[边缘节点]  STM32F103C8T6 + ESP8266 订阅指令
      │ 按指令调节"模拟充电功率"（PWM 占空比）
      ▼
[计量回传]  HLW8032 读取电压/电流/功率 → 上报 telemetry/station_1
      ▼
[大屏]  实时曲线显示"指令 vs 实测"跟随效果 + 偏差统计
```

一句话包装：**"平台输出的调度指令下发到自研充电桩节点，实测功率
跟随指令，跟踪误差 < 2%，验证了算法的物理可执行性。"**

## 2. 硬件清单（约 60 元）

| 器件 | 型号 | 用途 | 单价 |
|---|---|---|---|
| 主控 | STM32F103C8T6 最小系统板 | 边缘节点 | 12 |
| 计量 | HLW8032 模块（串联 0.001Ω 分流器版） | 功率计量 | 15 |
| 通信 | ESP8266-01S | MQTT 上网 | 8 |
| 负载 | 12V 灯泡/电热丝 + MOSFET 模块 | 模拟充电负载 | 10 |
| 其他 | 杜邦线/USB 转 TTL/220V 隔离注意 | — | 15 |

> 安全提示：HLW8032 接市电部分必须隔离操作；演示可用 12V 直流侧
> 替代市电侧（计量模块同样支持），**面试现场强烈建议用安全低压方案**。

## 3. 固件框架（Keil + 标准外设库，与你的手语手套同栈）

```
main.c
 ├── esp8266_mqtt.c    // AT 指令 + MQTT 订阅 dispatch/#，发布 telemetry/#
 ├── hlw8032_uart.c    // 4800bps 读功率帧，解析 Voltage/Current/Power
 ├── dispatch.c        // 收到目标功率 → PWM 占空比 = P_target/P_rated
 └── scheduler.c       // 1s 心跳上报 + 掉线重连 + 看门狗
```

关键代码量：约 600 行 C，你已具备全部所需技能（串口、定时器、PWM）。

## 4. 平台侧对接（新增 `edge/` 目录）

```python
# edge/mqtt_bridge.py —— 平台与节点的协议桥
# 订阅结果文件 results/curves.npz 的 pst_PPO (ours)，按时钟回放指令
# topic: dispatch/station_1  payload: {"t": 38, "p_kw": 96.4}
# topic: telemetry/station_1 ← {"v": 219.8, "i": 0.44, "p": 96.7}
```

大屏加一页"数字孪生回放"：指令曲线叠加实测散点。

## 5. 可以讲的面试问题

- 为什么用 MQTT 而不是 HTTP？（发布/订阅、弱网、QoS1、常驻连接）
- 15min 指令粒度太粗怎么办？（节点本地二次平滑：斜率限制 ramp-rate control）
- 通信中断的失效策略？（本地保底策略：维持上次功率 + 超时回退谷时充电）
- 计量精度校准？（对比标准表多点线性回归，讲出 ±0.5% 的量级即可）
